## Architectural Guidelines
- **Testing Policy (from AGENTS.md):** No frontend tests. No mocks in backend tests. Default to zero tests unless user explicitly requests, pure non-I/O algorithm, or bug regression. Test-first for bugs only.
- **Bidirectional Proxy Pattern:** Every hop uses two goroutines with `io.CopyBuffer` + `sync.Pool` 32 KiB buffers.
- **Fail-Fast Model:** POST failures, stream deaths, and pipe closures are terminal — sessions die and agents reconnect.
- **No Goroutine Leaks:** Every goroutine hangs off a context owned by its conn/session.
- **Control Stream Protocol:** Length-prefixed JSON messages with 4-byte big-endian length prefix (see `[S3]` `ReadControlMessage`/`WriteControlMessage`).
- **IPC Protocol:** AUTH handshake (`AUTH <len>\n<cred>` → `OK\n`), then REG or DATASTORE command.
- **Module ID Regex:** Single source of truth in `sdk.ModuleIDRegexp` — hyphens allowed in segments.

4. In `[S4]` `list()`, is `rows.Err()` checked after the iteration loop? What happens if the database connection drops mid-iteration?
5. In `[S4]` `get()`, does the error handler distinguish `pgx.ErrNoRows` from connection/query errors?
6. In `[S15]`, are terminal jobs ever removed from `m.jobs`? What is the memory impact under sustained load?
7. In `[S16]` `handleGet()`, is `wait_timeout` bounded? What prevents a client from holding the connection open indefinitely?
8. Does the migration in `[S1]` include an index covering `ORDER BY created_at DESC` in the list query (`[S4]`)?
9. In `[S17]` `handlePoll()`, if the extension disconnects after a job is dequeued from the channel but before `writeJSON` succeeds, is the job recoverable?
