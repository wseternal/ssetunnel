feat: agent module registry

PR #85 · agent-module-registry → main

Introduces a pluggable module system that extends the agent with external HTTP service processes. Modules register via local IPC (Unix sockets / named pipes), publish catalog snapshots through the control channel, and receive proxied HTTP invocations via reverse yamux streams. Includes a public Go SDK, digest-keyed UI asset trust, module metrics, console discovery UI, and three ADRs.

⚠️ Warning (no critical risks)

No critical risks identified on auth, session, or data-integrity paths. One medium-severity warning:

CORS origin reflection on invoke endpoint
internal/consoleserver/module_routes.go — handleInvoke OPTIONS handler
The OPTIONS handler reflects any Origin header as Access-Control-Allow-Origin. This grants credentialed cross-origin access from any domain. Mitigated by user-auth middleware and auth-header stripping before forwarding, but a strict allowlist is safer.

New internal/agentmod/ package with package validation (reverse-DNS module IDs, semver, symlink-hardened executable checks), owner-only IPC on Unix sockets and named pipes, credential-based auth (32-byte random hex via env var), and process supervisor with jittered exponential backoff (500 ms → 30 s).

★★★★★ Reverse Stream Invocation Proxy
Server sends module_open control message; agent opens reverse yamux stream with __module__ marker; one HTTP/1.1 exchange per fresh IPC connection. TOCTOU-safe slot reservation: 32 pending opens, 32 active invocations per agent, 8 per module.
internal/agent/module_invoke.go, internal/server/module_stream.go
★★★★★ Server Module Catalog Catalog
Session-scoped catalog reassembles agent snapshots via three-phase commit (start → chunk → commit). SHA-256 digest verification on commit. Worker pool (2 workers, queue depth 8) validates OpenAPI docs. Atomic catalog replacement. 5-minute reassembly timeout.
